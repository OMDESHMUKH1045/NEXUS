What is NEXUS?

Modern computers expose enormous amounts of system telemetry, but raw metrics alone don't automatically provide understanding.

NEXUS is being developed as a foundation for turning system behavior into structured, inspectable data. Core observation runs locally, on the machine being observed.

It focuses on

  • System observability
  • Workload behavior
  • Resource utilization
  • Performance investigation
  • Dataset generation and profiling
  • Reproducible analysis
  • Future intelligent reasoning over system telemetry

Engineering principles

Local-first

Core observation happens locally instead of requiring telemetry to be uploaded to an external service.

Read-only by default

The observability layer is designed to inspect system state without modifying the system.

Bounded

Sampling and process inspection stay bounded rather than becoming an uncontrolled system stress mechanism.

Inspectable

Transparent data structures, explicit models, reproducible behavior, and understandable outputs.

Incremental

Developed in clearly defined phases instead of attempting to build the entire platform at once.

From architecture to observability

  1. Phase 0 — ArchitectureCompleted

    Project scope, architecture, design decisions, roadmap, and task decomposition, established before implementation.

  2. Phase 1 — FoundationCompleted

    Repository foundation, core project structure, foundational models, CLI foundation, test infrastructure, and initial system contracts. Manually verified and integrated into the main branch.

  3. Phase 2 — Linux ObservatoryCompleted

    Linux observability for CPU and per-CPU utilization, CPU time and frequency, system load, memory and swap, PSI, thermals, disk counters, and bounded process snapshots. 22 passing tests; the nexus doctor and nexus observe workflows were verified. The sampler remains bounded and read-only and does not intentionally modify the system.

  4. Phase 3 — Dataset ProfilingImplemented / progressing

    Bounded synchronous CPU profiling with CSV output, JSONL output, read-only SQLite output, and chunked SHA-256 fingerprints. This phase bridges raw system observation and structured datasets that can later be analyzed.

Why build this?

System metrics are everywhere, but understanding system behavior is harder than collecting individual metrics.

A CPU percentage, memory value, load average, thermal reading, or process snapshot is only one piece of the story. NEXUS aims to provide a structured foundation where these observations can be correlated and analyzed together.

The long-term goal is to make complex system behavior easier to inspect, understand, and reason about.

Where intelligence fits

NEXUS is being designed with a future intelligence layer in mind. Claude and other advanced reasoning models could eventually operate over structured system observations. None of the following is implemented yet; the current foundation is focused on building trustworthy, structured observations first.
